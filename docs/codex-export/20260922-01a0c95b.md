### 成员 B：HLS/RTL 与 PPA

持续负责：

- 对参考实现进行性能分析，找出真正的热点模块。

1. 先验证数值正确性。
2. 再减少不必要的数据位宽。
3. 再优化 DDR 访问和片上数据复用。
4. 再做 `PIPELINE`、`DATAFLOW`、数组分区和循环展开。

## 四、必须在第一周冻结的接口

建议建立唯一的 `interface_v1.md`，至少包含：

- 输入/输出张量或数据块的尺寸。
- 数据类型和有效位宽。
- 定点数整数位、小数位及饱和规则。
- NCHW/NHWC 或自定义存储顺序。
- 行对齐、填充和地址对齐要求。
- AXI4-Stream、AXI4 Memory Mapped 或其他接口选择。
- 寄存器地址、启动位、完成位和错误位。
- 缓冲区所有权：谁申请、谁释放、何时可复用。
- 超时和复位行为。
- 软件函数原型和返回码。

接口冻结并不意味着内部实现不能变。B 可以不断重构加速器，只要从 A、C 看来，它还是同一个“插座”。

## 六、每周动态调整机制

每周开一次 45 分钟复盘，只回答五件事：

2. 当前距离 P0 闭环还差什么？
3. 最大瓶颈是算法、计算、带宽、时序还是系统稳定性？
4. 哪个任务已经阻塞超过两天？
5. 下周删掉什么，而不只是增加什么？

建议维护以下看板指标：

| 类别 | 指标 |
|---|---|
| 正确性 | 固定测试集通过率、最大/平均数值误差 |
| 算法 | 准确率、召回率或项目对应指标 |
| 性能 | 端到端延迟、核延迟、吞吐率 |
| 硬件 | LUT、FF、DSP、BRAM/URAM、目标频率、WNS |
| 系统 | 连续运行时间、超时数、崩溃数 |
| 交付 | 报告、视频、演示、构建复现完成度 |

触发重新分工的条件：

- 任一任务阻塞超过两天。
- 资源使用逼近器件上限，布局布线开始困难。
- 目标频率下时序连续一周无法收敛。
- 实际性能比目标低 20% 以上。
- 距离截止两周时，P0 仍不能完整运行。

时间分配建议：

- 前三周：70% 本人主线，20% 集成测试，10% 文档与备份。
- 后两周：40% 优化，30% 稳定性，30% 报告、视频和演练。
