### [09-29 19:00] 模型

按你们现在的演示目标，我建议把**主线定为 9 个算法环节**。它们共同完成：识别可通行地面 → 跟踪通用障碍物 → 在柱子遮挡时推算可能出现的区域 → 比较小车与障碍物的到达时间 → 实时给出通行、减速或绕行建议。

| 环节 | 建议采用的算法 | 可替换方案及选择理由 |
|---|---|---|
| 1. 相机标定与俯视图 | **棋盘格相机标定＋地面单应性变换（IPM）**。把地面上的位置映射到有尺度的俯视图，才能比较距离、速度和到达时间。 | 双目测距＋地面平面拟合：能处理更多与地面颜色相近的障碍物，但需要双相机同步、标定和更高算力。单应性只适用于地面，障碍物应取其**落地点或底部轮廓**来定位。[OpenCV 对单应性的说明](https://docs.opencv.org/4.0.0/d9/dab/tutorial_homography.html) |
| 2. 自车运动估计 | **轮速编码器＋IMU，采用互补滤波或扩展卡尔曼滤波（EKF）**。相机跟着车移动时，必须先知道“自己动了多少”，否则静止柱子也会被误判为移动障碍物。 | 地面特征点的稀疏 Lucas–Kanade 光流＋RANSAC：没有编码器时可用，但地面缺少纹理、反光时容易失效。若暂时用固定相机，只能作为开发阶段验证，不能代表移动小车演示。[OpenCV 光流教程](https://docs.opencv.org/4.12.0/d4/dee/tutorial_optical_flow.html) |
| 3. 可通行区域与障碍物提取 | **HSV/Lab 地面颜色分割＋形态学开闭运算＋连通域分析**。先确认哪些地面可见、可通行，再从其余区域提取有可靠底部位置的障碍物。计算规律，适合作为首个 PL 加速模块。 | Fast-SCNN 等轻量语义分割：适合复杂地面，但需要采集和标注数据；双目视差＋地面去除：对“与地面同色”的障碍物更有潜力，但集成难度更高。单纯帧差不适合作为主检测器，因为相机自身也在运动。[AMD Vitis Vision 已提供颜色检测相关算子](https://docs.amd.com/r/en-US/Vitis_Libraries/vision/overview.html_2) |
| 4. 俯视占用与可见性 | **三态栅格地图＋射线遮挡判断**：绿色是确认可通行，红色是已观测障碍物，蓝色是当前无法确认的区域。由柱子轮廓和相机位置算出柱后遮挡区。 | 概率占用栅格（log-odds）：多帧融合更细致，但参数和状态更新更复杂。首版三态地图更容易把每个颜色的依据讲清楚。 |
| 5. 多障碍物关联与跟踪 | **距离门控＋最近邻关联；多个目标接近时用匈牙利匹配＋恒速卡尔曼滤波**。在俯视坐标中维护每个障碍物的位置、速度和不确定度。 | α–β 滤波更简单，但不确定度表达较弱；ByteTrack适合基于检测框的多目标关联，可作为目标密集时的备选，但仍需将结果转换到地面坐标，才能用于速度和碰撞计算。[OpenCV 卡尔曼滤波接口](https://docs.opencv.org/4.11.0/dd/d6a/classcv_1_1KalmanFilter.html) |
| 6. 静止与移动判定 | **补偿自车运动后的地面坐标速度阈值＋滞回判定**。连续几帧速度超过阈值才判为移动，降到较低阈值后才改回静止，避免图标来回跳变。 | 光流可辅助发现运动，但不能直接把“画面中在动”当作“物体在动”。此环节不需要识别人、箱子等类别。 |
| 7. 短时预测与柱后遮挡 | **恒速卡尔曼预测＋有界加速度可达域＋遮挡状态机**。目标消失后继续预测；将“它在这段时间可能到达的范围”与“柱子造成的遮挡区”取交集，只把这部分标蓝。重现时用位置门控重新关联并更新轨迹。 | 恒加速度模型或 IMM 可应对变速，但加速度估计更容易受噪声影响；粒子滤波可表示多种可能路线，代价更高。首版用恒速中心轨迹配合逐渐扩大的可达域较稳妥。**遮挡期间无法保证知道它实际改变后的速度**；重新出现后可立即修正位置，速度通常还需要随后几帧估计。 |
| 8. 冲突判断 | **按时间采样的轨迹占用检测＋车身/障碍物尺寸膨胀**。检查未来同一时刻两者是否占据重叠区域，再比较减速或微调路线后的结果。这正对应你们要演示的“会不会在交叉点同时到达”。 | TTC（碰撞时间）或最近接距离可用于快速预警，但单独使用难以处理转弯、车身尺寸和柱后不确定区域。 |
| 9. 避让决策 | **有限候选轨迹滚动评估**：每次生成保持速度、减速、停车、向左/右小幅调整等可执行动作，预测短时轨迹，剔除碰撞和穿越高风险蓝区的候选，再选代价最低者。 | 有电动底盘且量到了速度、加速度、转向极限后，可升级为 DWA；MPC适合更精细的车辆约束，但建模和调参成本更高。手推车版本输出的是**实时建议路线与策略**，只有电动底盘才能验证自动执行。[DWA 原始论文](https://publications.ri.cmu.edu/the-dynamic-window-approach-to-collision-avoidance) |

**我推荐今天确定的组合**是：

> 单目相机标定/IPM → 地面分割与障碍物提取 → 编码器＋IMU 自车定位 → 三态俯视地图 → 地面坐标卡尔曼跟踪 → 恒速预测与遮挡可达域 → 分时碰撞检测 → 候选轨迹避让。

### [09-29 19:04] 模型

**双目会明显改变“怎样发现障碍物”，但不会替你们解决“怎样预测它的运动”。**对这次演示，双目最大的价值是测距离和高度：即使障碍物与地面颜色接近，也有机会通过它高出地面这一事实发现它。代价是两路相机同步、标定和视差计算，整链实现难度会明显上升。

| 演示环节 | 单目方案 | 换成双目后 |
|---|---|---|
| 障碍物检测 | 主要靠地面颜色或外观区分 | 先计算深度，再拟合地面；把**高出地面的区域**提为障碍物，可与颜色分割互相补足 |
| 距离与俯视图 | 假设地面平坦，用单应性把障碍物落地点映射到俯视图 | 由视差计算距离，再投影到俯视图；还能估计障碍物的高度和占地范围 |
| 静止／移动判断 | 补偿小车自身运动后，比较障碍物多帧位置 | **方法基本不变**，只是位置测量多了深度信息；仍需要编码器＋IMU或可靠的视觉里程计 |
| 柱后蓝色未知区域 | 根据柱子轮廓、目标消失前速度和可达范围生成 | 可用柱子的深度更准确地画出遮挡边界；**两只相机都看不到的柱后区域仍然未知** |
| 预测与避让 | 卡尔曼跟踪＋可达域＋分时碰撞检测＋候选路线评估 | **核心算法不变**，输入的位置与障碍物尺寸可能更可靠；目标在遮挡期间变速仍无法提前获知 |

双目增加的前端算法链是：

> 双相机标定与图像校正 → **StereoBM 或 StereoSGBM 视差计算** → 左右一致性检查、噪点过滤 → 深度重建 → 地面平面拟合／地面以上高度阈值 → 障碍物俯视投影 → 接入原有跟踪、遮挡预测和避让链。

我建议**软件原型先用 StereoSGBM，考虑 FPGA 加速时评估 StereoBM**。SGBM通常是更合适的深度质量起点；BM 的局部匹配结构更直接，但深度质量须用你们的场景实测。AMD 的 Vitis Vision 提供了 Stereo Local Block Matching 示例，这说明有可参考的硬件实现路径，**不代表它在你们的 KV260 整机上已经达到目标帧率**。[OpenCV 双目接口](https://docs.opencv.org/4.8.0/d9/d0c/group__calib3d.html)、[AMD Stereo Local Block Matching 文档](https://docs.amd.com/r/en-US/Vitis_Libraries/vision/stereolbm-bm.html)

实现难度上，我会这样判断：

- **采集与标定：显著更难。**左右画面要对应同一时刻，两个镜头的相对位置要固定；小车一移动，时间不同步会让移动障碍物产生错误深度。
- **障碍物检测：场景适应性更强，但调试更难。**深度能补单目颜色分割的短板；无纹理地面、反光、透明物体和遮挡边缘又可能没有可靠视差。**无效深度应标为蓝色未知，不能当绿色可通行。**
- **FPGA 工作量：明显增加。**视差需要搜索和缓存图像数据，资源、带宽、延迟都要量；后端的卡尔曼跟踪和路线决策则不需要重写。
- **实时性：不能因用了双目就保证。**深度的误差也随距离增大：近似关系是 \(Z=fB/d\)，其中 \(B\) 是两镜头间距，\(d\) 是视差；物体越远，视差越小，同样的视差误差会造成更大的距离误差。[OpenCV 双目深度原理](https://docs.opencv.org/3.0-last-rst/doc/py_tutorials/py_calib3d/py_depthmap/py_depthmap.html)

**针对你们的比赛演示，我的建议是：**如果场地可控、地面外观稳定，单目更容易把“遮挡预测—蓝色未知—重新出现—实时避让”整条链做完整。若你们想把“**不依赖障碍物颜色，也能发现通用障碍物**”作为主要亮点，双目更有说服力；但应采用**深度＋地面颜色融合**，不要只依赖深度。

KV260 有相机和 USB 接口，但“有两个接口”不等于现成的平台就能同步输出两路视频；选双目前，应把**实际相机能否稳定同步采集**作为第一个验证点。[AMD KV260 接口说明](https://docs.amd.com/r/en-US/ug1089-kv260-starter-kit/Interfaces)、[KV260 基础平台说明](https://docs.amd.com/r/en-US/ug1089-kv260-starter-kit/Vitis-Platforms)

对你们的项目，最合适的定位是：**面向遮挡场景的轻量时空世界模型**。它不生成未来视频，而是在俯视图中维护“现在知道什么、未来可能发生什么”。研究中的世界模型通常强调内部状态、预测以及利用预测选择行动；你们可以做一个范围明确的结构化版本，不必复现 Dreamer 这类大型学习系统。[World Models 原论文](https://arxiv.org/abs/1803.10122)、[DreamerV3 论文](https://arxiv.org/abs/2301.04104)

具体可以做成四步闭环：

1. **记住世界**：维护地面可通行区、静态障碍物、移动障碍物的位置与速度，以及蓝色未知区。目标进入柱后，轨迹不会立即消失。
2. **推演未来**：生成未来几个时刻的俯视占用图。遮挡目标的可能位置随时间扩散，蓝色区域只覆盖“柱后且目标可能到达”的范围。这与自动驾驶研究中的未来占用预测思路相关，但你们做的是规模更小、规则明确的版本。[Waymo 占用流预测论文](https://arxiv.org/abs/2203.03875)
3. **试走几条路**：在模型里分别推演“保持速度、减速、微调方向、停车”，展示各方案与未来障碍物占用区是否冲突。
4. **看到后立即修正**：目标从柱后出现，比较**预测位置与实际位置**，更新速度和未知区域；把误差显示出来。这一步最能证明模型真的在持续运行。

这样演示时，评委可以同时看到**当前画面、1 秒后的预测俯视图、各行动的风险比较**。柱后目标重新出现时，预测区域收缩、路线随之改变，故事线也很清楚。

如果你们还想让“世界模型”带有**学习能力**，可以加一个小型轨迹预测器作为升级项：输入目标最近若干帧的位置和速度，用小 GRU 或 MLP 输出未来位置及不确定度；与恒速卡尔曼模型对比。**只有在实测预测误差、遮挡后的安全决策确实更好时才采用它**。数据不足时，学习模型可能比恒速模型更不稳，不能仅凭“用了神经网络”说明更先进。

在 KV260 上，我建议的分工是：**PL 加速图像处理和俯视占用图更新，PS 维护世界状态、做短时推演与决策**。若要强调 FPGA 对世界模型本身的贡献，可在测时发现瓶颈后，将多时刻占用区域生成或候选路线碰撞检测做成 HLS 模块，并展示加速前后的整链延迟。

你们可以用这个名称描述作品：**“基于轻量时空世界模型的动态障碍物遮挡预判与通行决策系统”**。答辩时要主动说明边界：它是**结构化、短时预测的世界模型**，不是能理解任意场景、生成未来视频的基础模型。这个边界讲清楚，反而更经得起追问。

### [09-29 19:18] 模型

| 现有算法 | 在世界模型中的职责 |
|---|---|
| 俯视占用图、静态地图 | 表示当前环境状态：哪里可走、哪里有障碍、哪里未知 |
| 障碍物跟踪与卡尔曼滤波 | 保存目标的历史状态，并预测下一时刻的位置 |
| 柱后可达域 | 在看不见目标时，传播“它可能在哪里”的不确定性 |
| 重新出现后的数据关联 | 用新观测修正先前预测 |
| 候选路线滚动评估 | 在内部模型中试走不同动作，再决定现实中怎么走 |

**这些算法单独存在时，不足以支撑这个名称；合起来形成“状态 → 预测 → 观测修正 → 决策”的循环，就可以严谨地称为“结构化、短时预测的世界模型”。**世界模型研究的核心之一，正是利用内部环境模型推演未来并辅助行动；未来占用图也有相关研究先例。不过你们应明确说自己的模型是结构化的，而非论文中的大型生成式模型。[World Models](https://arxiv.org/abs/1803.10122)、[Occupancy Flow Fields](https://arxiv.org/abs/2203.03875)

我建议把它做成一个**明确的模块**，而非散落在各处的功能：

> 输入当前观测和小车状态 → 更新内部俯视世界状态 → 预测未来 0.5、1、1.5 秒的占用与未知区域 → 分别推演保持速度、减速、绕行 → 输出决策 → 下一帧对照预测并修正。

其中最有说服力的画面是：**障碍物进入柱后，模型继续给出随时间扩大的可能区域；它重新出现时，屏幕同时显示“先前预测”和“实际观测”，再看到模型如何收缩不确定度、修改路线。**这能让评委直接检查预测是否真的参与了决策。

“**学习**”则要单独讲清楚。卡尔曼滤波会根据新画面更新状态估计，但这不等同于训练了一个学习型世界模型。如果你们想使用“学习型”这个说法，需要再加入一个真正从数据学习的动态预测器，例如小型 GRU，根据过去轨迹预测未来位置分布，并用未参与训练的轨迹证明它优于恒速预测。做不出可靠提升，就保留结构化世界模型，**不要宣称学习型**。Dreamer 一类工作所说的学习型世界模型，要求确实学习环境动态。[DreamerV3](https://arxiv.org/abs/2301.04104)

答辩时，最能消除“蹭热度”质疑的不是名称，而是一个**去掉世界模型的对照实验**：同一段柱后遮挡录像，比较“只看当前帧”和“保留状态并预测”的出柱位置误差、危险路线选择次数，以及整链延迟。只要预测结果确实改变了避让决策，并且这些数据可复现，你们就有实质内容可讲。

所以我的建议是：**主线做扎实的结构化时空世界模型；小型学习预测器作为有数据、有对照结果时才加入的增强项。**

所以，今天可定的主线仍是：

> **感知 → 时空状态地图 → 卡尔曼跟踪与遮挡预测 → 多时刻未来占用 → 候选行动推演 → 新观测修正。**
