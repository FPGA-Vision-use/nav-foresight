# 定点加速器的数值验收

## 为什么有这份 skill

HLS 的仿真会给你三个"通过"，但它们**覆盖的失败模式完全不同**：

| 层 | 能挡住 | 挡不住 |
|---|---|---|
| csim（C 模型） | 算法/定点设计的算术错误 | HLS 的位宽推断、调度、接口生成 |
| cosim（RTL 仿真） | HLS 生成 RTL 的功能错误 | 综合/工具链、BD 连接、时钟复位、DDR 一致性 |
| **板级** | 上面全部 + 真实时序/访存 | —— |

结论：**只做前两层就宣布"通过"，等于把最难的那批问题留给现场。**

## 铁律

### 1. 参考值必须能自检

不要用"自己实现的另一份代码"当参考就完事——它也会错。做法是让参考值有一个**独立可核对的锚**：

- 优先用**原始实现自己记录下来的历史输出**（本项目是 `planner_frames.jsonl` 里每帧的浮点 margin）当锚，
  用它的输入重算一遍，要求 **0.0000 mm** 吻合；
- 没有历史记录时，用两组实现互证（C vs Python）并打印最大/中位偏差；
- 自检不通过就不要往下做——否则后面所有"不一致"都分不清是硬件错还是参考错。

### 2. 三层对拍，同一组输入

```
参考实现 ──csim──► 参考 dump ──cosim(同一 tb)──► RTL dump ──板级──► 板子 dump
                         每一层都要和上一层逐字节/逐位比
```

板级对拍不要只比"被选的那个结果"，要**dump 整个输出数组**（本项目是 43×400 个点 + 43×5 个 margin）。
只比一个数会让你错过"某一列整体偏一个常数"这种系统性错误。

### 3. 上板后先证寄存器，再谈功能

任何 HLS IP 第一件事：把**每个参数、每个地址寄存器**写一个唯一值再读回。
`regs` 子命令应该是驱动的第一个功能，而不是最后补的调试工具。

### 4. "差一个常数"先查位宽推断

如果某一列**整列恒定偏移**（本项目是 sweep 列整列少 512 mm），几乎一定是 HLS 的位宽/符号推断：
去生成的 RTL 里搜那条表达式的常量（`grep "9'd350"` 这种），确认中间量是几位、有没有 `$signed`。

修法不是改 C 的字面写法（HLS 会把 `a + 350 + t` 重新结合回去），而是**把常量换成运行时参数**——
运行时参数是全宽 int，HLS 无法收窄。

### 5. 用"频率扫描"分离瓶颈类型

实测比 HLS 估计慢时，把同一设计放到两个时钟频率下测，看**多出来的绝对时间**怎么变：

| 现象 | 类型 | 对策 |
|---|---|---|
| 多出的绝对时间不变 | 带宽型 | 减少数据量 |
| 多出的绝对时间 ×2 | 延迟型（每笔都等） | 增加 outstanding / 加宽端口 |
| 多出的绝对时间**越慢越差** | 事务型（每笔一个事务） | **加宽主机端口**，让一笔顶多笔 |

本项目就是第三类：32 位逐点写经 32→128 位宽转换器变成 17200 次窄写，
改成 128 位写后 26.5 → 12.9 ms，与 HLS 估计几乎完全吻合。

### 6. "改了没效果"先怀疑工具没重新生成

按顺序查：
1. 生成物的 md5 / 时间戳变了吗？
2. `export_design` 之类的输出目录**已存在时会静默空转**（本项目踩过）——换新目录；
3. 综合用的是**你改的那份源**吗？（IP 缓存、BD 里缓存的旧接口）
4. 板子加载的是新比特流吗？（比对板上 md5，看 dmesg 有没有 `writing ... to FPGA manager`）

## 交付形态

一个合格的"板级模块"交付应包含：

- 驱动：寄存器自检 + 单次调用 + 批量 + 计时，四个子命令；
- 验收：一条命令走完 加载→寄存器→冒烟→对拍→计时；
- 参考：能自检的参考生成器 + 一份固定输入/期望输出（可回归）；
- 文档：接口表（含"哪些寄存器在哪个口、间隔几字节"）、握手纪律、已知边界。

## 常见坑（按出现频率）

1. **`ap_done` 只是单周期脉冲**：不要用它判完成，只认 `ap_idle` 的 0→1 周期。
2. **AXI-Lite 地址寄存器在第二个口**（`s_axi_control_r`）；漏接时 Vivado **不报错**，
   判据是 hwh 里控制段数量 = IP 数 × 2。
3. **主从位宽不等宽时不要指望 SmartConnect**：全 AXI4-Lite 时它进 Low-Area 模式、不做位宽转换；
   要么把主口做成同宽，要么显式插 `axi_dwidth_converter`。
4. **CPU 与 PL 之间没有缓存一致性**：CPU 写完要刷，读 PL 输出前也要刷；
   `dma_heap` 的 mmap 是可缓存的（写带宽能到 GB/s 量级就是缓存态的迹象）。
5. **参数个数/顺序以 `fscanf` 次数为准**：给 C 测试台造文本输入时多写一个数，
   整份输入会错位一格，参考全错而看不出来。
6. **IP 版本号不升，综合会吃缓存**：改了 RTL 就把版本从 1.0 升到 1.1。

| 文件 | 用途 |
|---|---|
| `hw/clear_hw.py` | 驱动骨架：DmaBuf(dma_heap+pagemap)、寄存器读写、`regs` 自检、握手 |
